# Off Axis 720 / Back Full — 回転軸 3D教材（Phase 0.5）

モーグルの **Cork 720（FIS正式名称: Off Axis 720）** の回転構造を、選手とコーチが直感的に
理解するための Web ベース 3D 教材。研究用シミュレータではなく **教材**。

単一 HTML ＋ Three.js（CDN）。ブラウザストレージは使わない。

**中心メッセージ**
> TAKEOFF までは H（角運動量）を作れる。TAKEOFF 後は H はほぼ変えられない。
> しかし身体の形を変えれば、その H がどのような回転として現れるかは変えられる。

### この版で直した技術的欠陥（3点）

1. **ω と H を分離した。** `H0` は離地時に確定する prescribed vector（ワールド固定）として独立に持つ。
   `ω` は姿勢から数値微分して出す別量。両者はコード上で別変数・別概念。飛行中央で 30〜43° ずれる。
2. **Tilt の定義を変えた。** `tilt = asin(L̂·Ĥ)`（H に垂直な平面から身体長軸が外れた量）。
   「H と L のなす角」ではない。純粋なバック宙返りで **Tilt = 0°**。
3. **H を水平にハードコードしていない。** Cork の `h0InclinationDeg` は仮説パラメータ。

### 空中姿勢の生成方法

root orientation を自由キーフレームで作っていない。次の幾何変数から生成する：

| 変数 | 意味 |
|---|---|
| `H0` | ワールド固定。離地時に確定 |
| `tilt(t)` | 身体長軸が H に垂直な平面から外れる量 ← **A/B/C はここだけを変える** |
| `phi(t)` | L が H の周囲を回る位相（宙返り位相） |
| `psi(t)` | 身体長軸まわりの姿勢位相（ひねり位相） |

```
bodyY (L軸)  = L̂ = cos(tilt)(cosφ e1 + sinφ e2) + sin(tilt) Ĥ
bodyZ (T軸)  = Ĥ の L 直交成分 を長軸まわりに ψ だけ回したもの   （tilt=0 のとき T̂ = Ĥ）
bodyX (AP軸) = bodyY × bodyZ
```

その上に股関節・脊柱・腕・脚の local quaternion をキーフレームで重ねる。

`ψ̇ ∝ sin(tilt)` としてある（tilt がひねりを生む、という確立した関係）。合計ひねり量が
技の仕様に一致するよう正規化しているので、**A/B/C は合計は同じで、ひねりが立ち上がる
タイミングだけが変わる**。これがコーチに見比べてもらいたい差。

| 項目 | 実測値 | 実装箇所 |
|---|---|---|
| 滞空時間 | **1.65秒** | `VENUES.bf.airtimeS`（これを満たすよう `vy0` を逆算） |
| 宙返り量 | **ちょうど360°** | `HYPOTHESIS.bf.somersaultTurns` = 1.0、`tendency` 既定 0.80 で係数1.0 |
| 宙返りの進行 | 四分割で **0.27 / 0.28 / 0.21 / 0.24**（第3Qが最速） | `SOMERSAULT_PROFILES.bf.points` |
| 腕の振り上げ | **0.13秒**、離地の瞬間に頭上へ到達 | `SWING_T = -0.13` |
| 空中の姿勢 | 終始レイアウト（伸身） | `TRICK_DEFAULTS.bf.shape` = 0 |

### Back Full — `バックフルツイスト（正面）.MP4`（29.97fps・全150フレーム）で確定したこと

同じウォータージャンプ宮城の**過去の映像**。設備が当時と違うので見た目は bf.MOV と異なるが同じ施設。
滞空が約1.45秒と短いのは**スタート位置（進入速度）が違う**ため。別の台ではない。
→ **宙返りのタイミングと滞空1.65秒は bf.MOV のまま。この映像は腕と板の参照にだけ使っている。**

| 項目 | 実測 | 実装箇所 |
|---|---|---|
| 空中の腕 | 下表のとおり。**空中中盤は左右非対称** | `ARM_PROFILES.bf.keys`（左右独立・τで補間） |
| 板 | 離地から着水まで**終始2本そろって平行**。開かない・交差しない・割れない | 左右の脚を同一角度で駆動（独立ノイズなし） |
| 板 | 空中は膝ほぼ伸展、板は脚のラインの延長 | レイアウト姿勢（`shape` 既定 0） |

#### 腕（2026-08-18 測り直し）

初回の読み「+0.45から左右に開き始める」は**誤り**だった。実際は空中中盤で**左右非対称**になる。

| 局面 | 正面映像 T0基準 | **τ（実装はこれを使う）** | 腕 |
|---|---|---|---|
| 空中前半 | 0.00 〜 +0.30 | 0.00 〜 0.21 | 両腕を頭上〜体幹沿いに保持。ほぼ対称 |
| **非対称局面** | **+0.33 〜 +0.60** | **0.23 〜 0.41** | **片腕を体幹軸からほぼ真横（70〜90°）まで外転／反対の腕は体幹軸の近く（0〜30°）** |
| 空中後半 | +0.60 〜 +0.85 | 0.41 〜 0.59 | 両腕とも体幹に寄る。対称に戻る |
| 着水準備 | +0.85 〜 着水 | 0.59 〜 1.00 | ここで初めて左右対称に大きく開く。着水時は水平よりやや下 |

#### 立ち上がりの実測（正面映像 f57〜f62 を1コマずつ確認・2026-08-19）

| フレーム | τ | 腕 |
|---|---|---|
| f57〜f59 | 0.138〜0.184 | 非対称は確認できない |
| **f60** | **0.207** | 片腕が明確に外へ出始めている（立ち上がり途中） |
| **f61** | **0.230** | 非対称が完成。反対の腕が腰の位置 |

→ **立ち上がり開始 τ≒0.19 / 完成 τ≒0.23**（いずれも ±0.05）。キーは `0.19 → 0.245`。

- 誤差は**±2フレーム（±0.067秒 ＝ ±0.046τ）**。
- **f57〜f59 は反対側の腕が体幹の陰に入って見えない。**
  「対称だった」ではなく **「非対称が確認できなかった」**。それ以前に非対称が無かったとは言えない。
- **ポールの向き ≠ 腕の向き。** ポールは腕より長く伸びているため、腕の方向は胴体との位置関係から読んでいる。

補間は smoothstep。ease-in（u³）にすると τ0.20 が 11.78° になり、
映像（τ0.207 で立ち上がり途中）より遅くなるので採用しない。

- **τ（正規化滞空時間）で当てている。** 映像の滞空1.45秒とアプリの1.65秒が違うため、秒をそのまま使わない。
- 角度は**目視実測、精度±15°**。これ以上細かくは測れていないので中間値を刻んでいない。
- **左右どちらの腕が外転側かは映像から確定できていない。** コードは「外転する側 / 体幹に寄せる側」
  として持ち、`sideAssignment` で仮に左を外転側に割り当てている。
- Cork 側（`ARM_PROFILES.cork`）は未測定のまま。左右対称・秒ドメインで挙動は従来どおり。

**左右非対称の意味**：左右非対称な腕の動きは、実写で身体長軸を H に対して傾ける（＝tilt を作る）動作。
左右対称に上げ下げしても慣性モーメントが変わって宙返りの速さが変わるだけで、tilt は生じない。
**ただし現行の運動学モデルでは腕は回転にフィードバックしないので、非対称にしても tilt や ψ は変わらない
（見た目のみ）。** これは正しい状態で、物理的な接続は Phase 2 の物理モードで作る。
`ARM_PROFILES` は物理ソルバへの関節角入力としてそのまま渡せる形（`anglesAt(x)`）にしてある。

なお非対称の窓（τ0.23〜0.41）は板の面の入れ替わりの直前に来るが、
**単一視点なので因果は断定できない。順序が一致した、という以上のことは言えない。**

#### 計測値を報告するときの注意

- **腕の左右差は `身体の形`（shape）に強く依存する。** タックするほど両腕が体側に寄るので差は縮む。
  `shape=0`（bFの既定・レイアウト）で 62.4°、`shape=0.12` で 44.5°。
  **どのパラメータで測ったかを書かずに角度だけ report しないこと。** `OA720.state()` を併記する。
- `OA720.setParams({trick:'bf'})` は技が変わるとき `TRICK_DEFAULTS` を適用してから
  引数を上書きする。UIのボタンで切り替えた場合と同じ状態になる。
  （以前は既定値を適用していなかったため、プログラムから切り替えると shape が
  前の技の値のまま残り、UI と違う状態で計測されるという食い違いが起きた）
- **板の面の符号反転は飛行中に2回ある**（`shape=0` で τ=0.475 と τ=0.940、
  `shape=0.12` で τ=0.449 と τ=0.892）。位置はパラメータ依存。
  **2回目は正面映像では読めない区間**：τ0.85以降は選手がフレーム下端に近づき、
  板が暗いデッキと重なるか画面外に出る（f90〜f94 はブーツしか見えない）。
  実写で否定も肯定もできないので、**合わせ込みも削除もしない**。比較は1回目どうしで行う。

### 実測できていないこと

**ひねりが「いつ」始まってどう進むかは、どちらの映像からも判定できない。**
単一視点・手持ちパンのため、身体長軸まわりの回転位相を信頼できる形で読めない。

したがって `ψ(t)` と **A/B/C プリセットは引き続き仮説**であり、`［仮説］` バッジを付けたままにしている。
ひねりの発生タイミングが未確定であること自体が、この教材が問いたいことなので、
プリセットは実測が出るまで残す。

### 正面から見た「板の面の入れ替わり」— 現行モデルと実写のズレ

正面映像では、板の面が飛行中に1回だけ入れ替わり、**中心は T0+0.57s（その映像の滞空の約40%）**。

現行モデルでも入れ替わりは1回起きるが、**滞空の47.5%**（T0+0.78s）で、実測より約0.09（滞空比）遅い。
無理に合わせていない。候補は2つあり、この1視点からは分離できない。

1. 別の試技なので、そもそも宙返りの進み方が bf.MOV と違う（進入速度が違うことは分かっている）
2. 板の面の見え方が、現行モデルほど宙返りだけで決まっていない

さらに分かったこと：**この入れ替わりの位置は A/B/C プリセット（ひねりの立ち上がり）を変えても1ミリも動かない。**
動くのは「上半身の抜け方」（離地時の傾き）だけ（exit=0.9 → 43.5% / 0.5 → 50.2%）。

これは現行スキャフォールドの構造的な性質。板の面の法線を身体長軸 L と平行に置いているため、
**L まわりの回転である ψ（ひねり）は板の面の見え方を原理的に変えられない。**
実際には板は脚の延長で L からわずかに外れているので、ひねりは面の見え方に効くはず。
Phase 2 で多剛体に差し替えるときに解消する見込みの制約として記録しておく。

## 仮説パラメータの置き場所

`index.html` の **`HYPOTHESIS` オブジェクト1箇所**（「1. HYPOTHESIS」ブロック）。
各項目は `{ value, hyp, note }` を持ち、`hyp: true` のものは UI（BODY AXES → Advanced）にも
「［仮説］」と表示される。

| 技 | パラメータ | 既定値 | 仮説か |
|---|---|---|---|
| Cork 720 | `h0InclinationDeg` H0の水平からの傾き | 18° | **仮説** |
| | `somersaultTurns` H まわりの周回 φ | 1.00 | **仮説** |
| | `twistTurns` 長軸まわり ψ | 1.50 | **仮説**（L累積 ≒540° 説に対応） |
| | `tiltMaxDeg` tilt ピーク | 46° | **仮説** |
| Back Full | `h0InclinationDeg` | 0° | 確立寄り（ほぼ純粋な宙返り＋ひねり） |
| | `somersaultTurns` | 1.00 | **実測** |
| | `twistTurns` | 1.00 | 確立寄り（bFの定義） |
| | `tiltMaxDeg` | 24° | **仮説** |

`TILT_PRESETS`（A/B/C の tilt(t) プロファイル）も同じブロックにある。
`SOMERSAULT_PROFILES`（宙返りの進行プロファイル）は**仮説ではなく実測値**なので、
すぐ下の別ブロックに `measured` / `source` を付けて分けてある。

**確立した原理としてエンジン側にハードコードしてあるもの**（仮説ではない）
- 飛行中 H はほぼ保存される（`H0` は飛行中一定）
- 身体形状（慣性）が変われば同じ H でも回転の速さが変わる（`shapeFactor`）
- ひねりの立ち上がりは tilt が作る（`ψ̇ ∝ sin(tilt)`）
- 着地に向けて tilt を戻すとひねりが止まる（`landFade`）

**数値を確定事実として UI に書かない。** 「Contact 37% / Aerial 63%」のような比率表示は
まだ測定していないので入れていない（Advanced にもその旨を明記）。

## 物理モード［実験］（Phase 2・Back Full 専用）

`運動学モード（実測再現）` と並列の**別モード**。既存の運動学モードには手を入れていない。
**Cork では選べない**（実測が無く、仮説を入れると出力が「計算結果」の顔をしてしまうため）。

- 操作できるのは **「離地の瞬間の軸の傾き（台の中で作る）」** の1つだけ。
  これは**入力**（台の中で作るもの）で、ひねりは**出力**。禁止している「結果を直接動かすスライダー」ではない。
  離地後は他の台の中の入力と同じく**ロックされる**。
- 空中の腕は実測プロファイルに固定。動かせない。
- **ひねりの向き（左右）は出さない。** `sideAssignment` が仮置きで符号が仮のため、大きさだけを表示する。

### 計算はオフライン

ブラウザでは解かない。`phase2/` のソルバで解いた結果を `PHYSICS_TABLE` に
**(tilt, phi, psi) の3つ**で持ち、`rootQuatFrom()` で姿勢を復元している（復元誤差 3×10⁻⁶ °）。
描画経路は運動学モードと共通。詳細は [phase2/README.md](phase2/README.md)。

### このモデルが言っていること

| 離地の傾き | ひねり量（大きさ） |
|---|---|
| 0° | 約 6°（＝空中の腕だけではほとんど出ない） |
| 5° | 約 155° |
| 10° | 約 334° |
| 15° | 約 620° |

- **空中の腕が作れる傾きは 2.5°（ポール無）〜3.4°（0.25kg仮）程度**で、必要量の 1/4 ほど。
- ひねり360°に必要な離地の傾きは、このモデルで **約10〜11°**、剛体近似で **約8°**。
  幅のある値として扱う（1試技のみ／物理量はすべて仮／腕プロファイル±15°）。
- **「台の中で作られている」と断定はしない。「このモデルではそうなる」まで。**

## 意図的に入れていないもの

- 角度の足し算表示（「L軸540° + T軸180° + AP軸180°」など）
- 結果の角度を原因として直接操作するスライダー（`Cork angle 35°` など）
- H の数値的な大きさ（向きだけを表示）
- contact / aerial の比率の数値
- `Twist input` という名称（「空中でひねりという力が追加される」と読めるため廃止）
- ブラウザストレージ

## 用語

- FIS 正式名称は **Off Axis 720**。「3D」は FIS の正式技名ではない。
- `Rotational Jumps / 720 Position (7p)` と `Off Axis Jumps / Off Axis 720 Position (7op)` は別カテゴリ。
  **Back Full は `Inverted Jumps (bF)` で、さらに別カテゴリ。** コークの一種ではない。
- 「ゼロ角運動量ツイスト（猫ひねり）」「トランポリンのターンテーブル」
  「twisting somersault の tilt 由来ツイスト」を同一視しない。
  ターンテーブルはベッドとの接触で角運動量を受け取れるのでゼロ角運動量運動とは限らない。

## 使い方（コーチ向け）

1. 上部で技を選ぶ（Cork 720 / Back Full）。会場・初期値・カメラがまとめて切り替わる。
2. 「台の中」の2つのスライダーで離地条件を作る。
3. ▶ 再生。**離地の瞬間に H 矢印が出て向きが固定され、台の中の入力がロックされる。**
4. 空中の「軸の作り方」を **A と B で見比べる**。合計のひねり量は同じで、
   ひねりが立ち上がるタイミングだけが変わる。実際のコークはどちらに近いか。
5. 「身体の形」は離地後も動かせる（H は同じでも回転の現れ方が変わる）。
6. `BODY AXES` で L/T/AP・ω・仮説パラメータ・検算モードを表示。

カメラは 横／斜め／後ろ／**正面**／H方向 のプリセットと自由回転。
「正面」は進行方向から見る検証用ビューで、板の面の入れ替わりを見るのに使う。

`?capture=1` を URL に付けると canvas を画像として保存できる（検証用。描画結果は変わらない）。
